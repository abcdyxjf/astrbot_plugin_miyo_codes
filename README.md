# 米哈游前瞻兑换码 · AstrBot 插件

原神 / 崩坏：星穹铁道 / 绝区零 每次版本前瞻直播都会发兑换码，通常**第二天就过期**。
群里那几位经常是隔天才看到、才想起要换——这个插件在你睡觉的时候把码发到群里。

- 码来自**官方接口的原始数据**，不是从玩家帖子里抄的，不会抄错、抄漏、抄到国际服
- 只在「码全部揭晓 + 直播已结束 + 再等 N 分钟」之后才发，不发残缺消息
- 群里有人贴直播间链接就自动接住，不用改配置

发出去长这样：

```
【崩坏：星穹铁道 · 4.7版本前瞻 兑换码】
① 永远不会抛弃你
   └ 星琼×100，信用点×50000
② 永远不会欺骗你
   └ 星琼×100，漫游指南×5
③ 星神阿哈祝福你
   └ 星琼×100，提纯以太×4

⏰ 有效期至 10-31 23:59，过期就作废了
🗓 4.7 版本 11-11 上线，12-23 结束（共 42 天）
📮 游戏内 菜单 → 兑换码（或设置 → 账号 → 兑换码）
```

---

## 安装

**要求**：AstrBot ≥ 4.17.0，平台适配器是 OneBot v11（aiocqhttp / SnowLuma 等）或官方 QQ 机器人。

**从插件市场**：面板 → 插件市场 → 搜「米哈游前瞻兑换码」→ 安装 → 重载插件。

**手动**：把整个目录丢进 `AstrBot/data/plugins/`，重载插件。

> 本插件**没有必装依赖**。`rapidocr_onnxruntime` 是可选的，见文末「依赖」一节。

---

## 三步跑起来

**第 1 步：告诉它发到哪。**

面板 → 插件配置 → `target_groups` 填群号（`target_friends` 填 QQ 号可发私聊）。
两个都留空就什么都不发——这是故意的，装上就往陌生群里发消息是最不能接受的事。

**第 2 步：把直播间链接发到群里。**

前瞻当天群里总会有人转直播间链接。插件会在后台接住它，不用你做别的：

```
https://webstatic.mihoyo.com/bbs/event/live/index.html?act_id=ea202610261626345889&game_biz=hkrpg
```

也认光秃秃的 `ea` + 18 位数字。接住之后它自己会判断这场是哪款游戏、结束没有、码齐不齐。

**第 3 步：等。**

直播结束 + 15 分钟，码就出来了。`/兑码状态` 随时能看到它现在盯着什么。

## act_id 从哪来（新用户必读）

米哈游**没有**「列出所有前瞻直播」的接口。每场直播的 ID（`ea202610261626345889` 这种）
只能从外面拿到，**这一环没法全自动**——这是插件的设计前提，不是 bug。

我试过从官方预告帖自动挖 act_id：拉了星铁 4.7 和原神 7.2 的预告帖全文、前瞻节目帖全文，
**正文里既没有 act_id，也没有直播间链接**（那几篇只有几百字的活动文案）。
所以只能靠下面三条路，按优先级：

| 优先级 | 来源 | 怎么用 |
|---|---|---|
| 1 | 配置里手填 | 面板 → 插件配置 → `act_overrides`，一行一个：`hkrpg=ea2026...` |
| 2 | **群里贴链接** | 谁把直播间链接发到群里，插件自动接住，**推荐用这个** |
| 3 | 上次用过的 | 状态文件里的记录，同一场不会重复问 |

不知道链接去哪找？米游社 App 的直播入口、B 站前瞻直播页、官号动态里都有，
反正群里总会有人发。也可以直接发指令 `/兑码 <链接>` 手动灌进去。

## 指令

| 指令 | 作用 |
|---|---|
| `/兑码` | 立刻检查所有启用的游戏，有齐全的码就发（忽略"已发过"） |
| `/兑码 <直播间链接或 act_id>` | 记住这场直播并立即检查 |
| `/兑码状态` | 看三个游戏当前挂的 act_id、来源、版本周期、最近发过哪几场 |

## 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关，关掉后不再自动发（指令仍可用） |
| `platform_id` | 空 | 用哪个平台实例发。**留空自动挑一个支持主动推送的**，同时挂了多个平台才需要手填 |
| `target_groups` | `[]` | 发到哪些群；填了才发，新加的群会自动补发当前场次 |
| `target_friends` | `[]` | 发到哪些人的私聊；对方得是机器人的好友 |
| `games` | 三款全开 | `hkrpg` = 星铁 / `ys` = 原神 / `nap` = 绝区零 |
| `act_overrides` | 空 | 手填场次，一行一个 `游戏=act_id` |
| `poll_interval_sec` | `180` | 直播时段内查询间隔 |
| `slow_poll_interval_sec` | `1800` | 其余时段查询间隔 |
| `active_hours` | `17:00-23:59` | 没有预告时的兜底高频窗口（有预告就按预告走，不看钟点） |
| `post_delay_min` | `15` | 直播结束后再等几分钟才发 |
| `require_all_codes` | `true` | 等接口里的码全部揭晓才发 |
| `partial_grace_min` | `60` | 有码一直不揭晓时，等这么久就先发已有的（`0` = 一直等） |
| `min_codes` | `1` | 码数下限，防止接口返回残缺数据就发 |
| `remind_before_min` | `30` | 直播前多久在群里提醒要链接（`0` = 不提醒） |
| `ask_for_link` | `false` | 兜底：在 `active_hours` 内没 act_id 时也问一句 |
| `stale_hours` | `48` | 直播开始超过这么久就不发，防止把旧场次的码当新的发 |
| `state_file` | 空 | 状态文件路径。**留空自动放在 `data/plugin_data/` 下**，一般不用改 |

## 什么条件下才会发

三条同时满足才发，缺一条就不发：

1. **码要齐**：接口里返回几个码就等几个**全部揭晓**（`require_all_codes`）。
   直播中码是逐个放出的，提前发就是一个少一个码的残缺消息，群里还得补一次。
   > 这里**不能**写死"至少 3 个"：绝区零一般只发 **1 个码**，写死 3 就永远发不出去。
   > 兜底：某个码万一一直不揭晓，超过 `partial_grace_min`（默认 60 分钟）就先发已有的。
2. **要够晚**：`max(直播结束, 最后一个码揭晓时刻) + post_delay_min` 之后才发。
   直播常超时，预告时长不能当依据；接口的 `live.end` 才是准的。
3. **这一场没发过**（按 act_id + 码内容指纹去重）。
   去重是**按群 / 按人**分别记的（`g:群号` / `f:QQ号`）：临时加一个群或一个 QQ，
   它会自动给你补发当前场次，而已经收到过的地方不会再被刷一遍。

另外，直播开始超过 `stale_hours`（默认 48 小时）的场次一律不发。

## 直播时间从哪来：读官方预告，不猜星期几

三家官号都会在前瞻前 2~4 天发一条「前瞻特别节目预告」，正文里写着具体时刻：

> 2026年10月30日19:30，锁定官方直播间

插件每 6 小时读一次（三家各一次），解析出下一场时间。用来：

1. **决定轮询频率**：开播前 30 分钟到结束后 6 小时高频查，其余时间半小时一次。
   直播时间不固定——周五居多，但周六、周日都出现过，原神春节档还放在中午 12:00。
2. **开播前 30 分钟提醒**群里丢链接（仅在没有 act_id 时）。
3. `/兑码状态` 里能看到下一场是什么时候。

## 版本有多长：读游戏内公告

版本周期**不是固定 42 天**。星铁实测：4.5 是 33 天（08/26 → 09/28）、4.6 是 44 天
（09/28 → 11/11）。拿 6 周硬推下一次前瞻，会差出一整周。

所以插件不猜，直接读官方写死的时间。**主路径是游戏内公告**：

```
「4.6版本「月升之前，与兽共舞」版本更新说明」  2026-09-28 07:00 ~ 2026-11-11 07:00
```

这条公告的**结束时间就是版本的结束时刻**，而它正好是下一版的上线日。三家都成立：

| 游戏 | 公告 | 结束时间 | 对照 |
|---|---|---|---|
| 星铁 | 4.6版本更新说明 | 2026-11-11 07:00 | 4.7 于 11-11 上线 ✓ |
| 星铁 | 4.7版本商店上新 | 2026-12-23 06:00 | 4.7 共 42 天 ✓ |
| 原神 | 7.1版本更新说明 | 2026-11-04 06:00 | 7.2 于 11-04 上线 ✓ |
| 绝区零 | 3.3版本更新公告 | 2026-12-02 06:00 | 3.3 共 42 天 ✓ |

这个接口**免登录、结构化、三家通用、不用 OCR**，而且很快（0.1~0.2 秒）。

意外收获：**上一版的结束日就是这一版的开始日**，所以只要公告里连着两个版本，
连「这一版哪天开始」都不用别人告诉它：

```
4.6 结束 11-11  →  4.7 从 11-11 开始，到 12-23 结束，共 42 天
```

前提是版本号对得上：新版本上线前，公告里还是上一版的「更新说明」，它的结束日是
**新版本的上线日**，不是新版本的结束日。代码会校验版本号，对不上就先不显示，
等新版本上线后自动补上。

`/兑码状态` 里显示成：

- 版本进行中：`本版周期：3.3 10-21 ~ 12-02（42 天） 进行中`
- 还没上线：`下一版：4.7 11-11 ~ 12-23（42 天）` + `下一场前瞻预计：12-11 前后`
- 刚结束：`上一版：… 已结束`

### 兜底：星铁的「版本速览」长图（OCR，可选）

公告接口哪天挂了，插件会退回 OCR 官方「…版本速览」长图——那张图的日期栏长这样：

```
版本更新  09/28          版本结束  11/11
```

这行字**是画在图里的**，帖子里一个字都没有，所以要 OCR：
只取图片顶部 35%，按「版本更新」「版本结束」两个标签的 **x 坐标**对齐日期
（表格中间还夹着分期日期，不能简单取第一个和最后一个）。

> 只有星铁有这种长图：原神没有，绝区零的《情报总览》是 15000px 长海报、
> 日期不在同一块版面上，硬 OCR 又慢又不准。
> 没装 OCR 库也能跑，只是这条兜底路径失效。

## 依赖

- 取码、发码、读公告：**只用标准库 + AstrBot**，不需要任何第三方库。
- `rapidocr_onnxruntime`：**可选**，只给上面那条 OCR 兜底路径用。
  ```bash
  pip install rapidocr_onnxruntime
  ```
  它会连带装 onnxruntime（约 45MB）和 opencv（约 108MB）。小机器、树莓派、空间紧张就别装，
  不影响正事。装的话建议加 `--no-deps`，避免把 numpy / opencv 升到别的版本影响其它插件。

## 报错排查

| 现象 | 看这里 |
|---|---|
| 一直不发 | 日志搜 `[miyo_codes]`；多半是没拿到 act_id（`/兑码状态` 里显示"未设置"） |
| 日志说"没有可用平台实例" | 面板里平台没连上，或插件配置的 `platform_id` 填错了；留空可自动探测 |
| 发了空消息 / 只发了一半 | `refreshCode` 只返回已揭晓的码；等直播结束再看 |
| 重复发 | 检查 `state_file` 是否可写；写不进去会每次都当新场次 |
| act_id 报"属于 xx 不是 xx" | 配置里串场了，改 `act_overrides` |
| `/兑码状态` 里没有版本周期 | ① 新版本还没上线（公告里还是上一版的更新说明，属正常）；② 公告接口挂了，看日志 |
| 缺"版本周期"且日志有 `retcode=1034` | 米游社详情接口限流，已自动冷却 5 分钟，半小时后重试 |
| 私聊发不出去 | 对方得是机器人好友；日志里会有 `发到 私聊xxx 失败` |

## 数据源与已知限制

**取码**（免登录，就是米游社直播间页面自己用的那个）：

```
GET https://api-takumi.mihoyo.com/event/miyolive/index?act_id=<场次ID>
    → 直播标题 / 开始 / 结束 / 是否结束

GET https://api-takumi.mihoyo.com/event/miyolive/refreshCode?act_id=<场次ID>&time=<秒>
    → code_list：每个码 + 奖励 + to_get_time（这个码在直播里"揭晓"的时刻）
```

**踩过的坑**（写在这里省得后来人再踩一遍）：

- 搜索接口 `searchPosts` 按相关度排，**新发的帖子常常还没收录**。只靠它会漏掉当下这场。
- `userPost` 按时间倒序，但官号一天发十条，往前几天就到底了，三周前的预告又没了。
  **所以两个源都拉，按 post_id 合并去重。**
- 列表接口返回的正文是**被截断的摘要**（一百来字），失效时间和上线日期都在这段之外，
  必须再请求 `getPostFull` 读全文。
- 详情接口会**限流**：密集请求返回 `retcode=1034`，此时 `data` 是空的、`content` 是 `None`，
  必须当错误处理，否则会被当成"这帖没正文"静默漏掉整期速览。
  现在的处理是：识别到 1034 就**整体冷却 5 分钟**快速失败（实测把整轮轮询从 40 秒降到 0.7 秒）。
- 游戏内公告接口**是另一个域名**，跟米游社的限流互不影响。

**还没验证的**：

- 原神 / 绝区零的直播还没真正跑过一次自动发码（接口、预告、失效时间、上线日期都已解析正确）。
- 直播时长只有星铁 4.7 实测过（77 分钟）。三款都可能超时，所以代码不按时长推，只认 `live.end`。
- 公告 `end_time` 理论上是"公告有效期"，米哈游有可能为展示而延期。目前四期实测全部等于版本结束日；
  真出现偏差，最坏是周期算错几天，不影响取码发码。
