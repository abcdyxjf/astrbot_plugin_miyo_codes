# 米哈游前瞻兑换码 · AstrBot 插件

<img src="logo.png" width="96" alt="logo">

原神 / 崩坏：星穹铁道 / 绝区零 每次版本前瞻直播都会发兑换码，通常**第二天就过期**。
群里那几位经常是隔天才看到、才想起要换——这个插件替你在后台守着，直播结束当天把码发进群。

- 码来自**官方接口的原始数据**，不是从玩家帖子里抄的，不会抄错、抄漏、抄到国际服
- 只在「码全部揭晓 + 直播已结束 + 再等 N 分钟」之后才发，不发残缺消息
- 没到前瞻窗口**一个请求都不发**；三款游戏各算各的节奏，互不干扰
- 群里有人贴直播间链接就自动接住，不用改配置
- **新装即用**：自带一份出厂预置的版本周期，不用等第一轮联网

发出去长这样：

```
【崩坏：星穹铁道 · 4.7版本前瞻 兑换码】
① 永远不会抛弃你
   └ 星琼×100，信用点×50000
② 永远不会欺骗你
   └ 星琼×100，漫游指南×5
③ 星神阿哈祝福你
   └ 星琼×100，提纯以太×4

⏰ 有效期至 10-31 23:59，过期就作废了
🗓 4.7 版本 11-11 上线，12-23 结束（共 42 天）
📮 游戏内 菜单 → 兑换码（或设置 → 账号 → 兑换码）
```

## 安装

**要求**：AstrBot ≥ 4.17.0，平台适配器为 OneBot v11（aiocqhttp / SnowLuma 等）或官方 QQ 机器人。
**没有必装依赖**，`rapidocr_onnxruntime` 是可选的，见「依赖」一节。

- **插件市场**：面板 → 插件市场 → 搜「米哈游前瞻兑换码」→ 安装 → 重载插件
- **手动**：整个目录丢进 `AstrBot/data/plugins/` → 重载插件

## 三步跑起来

**1. 告诉它发到哪。** 面板 → 插件配置 → `target_groups` 填群号（`target_friends` 填 QQ 号可发私聊）。
两个都留空就什么都不发——这是故意的，装上就往陌生群里发消息是最不能接受的事。

**2. 等。** 装好就不用管了。`/兑码状态` 随时能看到它现在盯着什么、下一步什么时候动。

**3. 万一没接住。** 前瞻当天把直播间链接丢进群里，插件自动接住，不用改配置：

```
https://webstatic.mihoyo.com/bbs/event/live/index.html?act_id=ea202610261626345889&game_biz=hkrpg
```

也认光秃秃的 `ea` + 18 位数字，或者直接发指令 `/兑码 <链接>`。

## 指令

| 指令 | 作用 |
|---|---|
| `/兑码` | 立刻检查所有启用的游戏，有齐全的码就**强制重发**。默认只给群管理员、私聊和 `admin_users` 名单 |
| `/兑码 <直播间链接或 act_id>` | 记住这场直播并立即检查（任何人都能用，这是提供链接，不是重发） |
| `/兑码状态` | 三个游戏当前挂的 act_id、来源、版本周期、下一场时间，以及「节奏」一行 |
| `崩铁兑换码` / `星铁兑换码` / `原神兑换码` / `绝区零兑换码` | **只回在当前会话**，取当前场次的码。直播没结束也能用，已揭晓的码在游戏里就能换 |

最后那条是给群里准备的：有人知道今晚直播、快结束了想赶紧换，发一句话就行，
不用记指令、不用加斜杠。它**不广播到别的群**，同一款 60 秒内只回一次。

## 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关，关掉后不再自动发（指令仍可用） |
| `platform_id` | 空 | 用哪个平台实例发。**留空自动挑一个支持主动推送的**，挂了多个平台才需要手填 |
| `target_groups` | `[]` | 发到哪些群；填了才发，新加的群会自动补发当前场次 |
| `target_friends` | `[]` | 发到哪些人的私聊；对方得是机器人的好友 |
| `games` | 三款全开 | `hkrpg` = 星铁 / `ys` = 原神 / `nap` = 绝区零 |
| `act_overrides` | 空 | 手填场次，一行一个 `游戏=act_id` |
| `poll_interval_sec` | `180` | 直播时段内查码间隔（最小 60 秒，填更小按 60 执行） |
| `slow_poll_interval_sec` | `1800` | 其余时段查码间隔（同上） |
| `post_delay_min` | `30` | 直播结束后再等几分钟才发 |
| `require_all_codes` | `true` | 等接口里的码全部揭晓才发 |
| `partial_grace_min` | `60` | 有码一直不揭晓时，等这么久就先发已有的（`0` = 一直等） |
| `min_codes` | `1` | 码数下限，防止接口返回残缺数据就发 |
| `remind_before_min` | `30` | 直播前多久在群里提醒要链接（`0` = 不提醒；开播两小时后仍无链接会再催一次） |
| `ask_for_link` | `false` | 兜底：开播前 3 小时起仍没 act_id 时，在群里问一句 |
| `nav_auto` | `true` | 自动从米游社版区工具列表发现 act_id（直播前后约 29 小时内有按钮） |
| `ask_game_codes` | `true` | 允许群友用「崩铁兑换码」这类话直接取码 |
| `admin_users` | `[]` | 允许 `/兑码` 强制重发的 QQ 号；留空 = 群管理员和私聊可用 |
| `stale_hours` | `48` | 直播开始超过这么久就不发，防止把旧场次的码当新的发 |
| `state_file` | 空 | 状态文件路径。**留空自动放在 `data/plugin_data/` 下**，一般不用改 |

## 它什么时候发请求、什么时候发码

**核心原则：没到该动的时候，一个请求都不发。**三款游戏各有一套独立的计时器，
星铁进直播不会把原神和绝区零也拖着一起问。

**版本周期**（每款的版本结束日）平时 **24 小时**对一次——这个值一天最多变一次，问勤了没用。
前瞻窗口内缩到 6 小时；还不知道周期、或周期已过期时 1 小时。

**新装用户不用等这一轮**：插件自带一份出厂预置的版本周期（`/兑码状态` 里标「（出厂预置）」），
装载后一直睡到「推算的前瞻窗口开始」那一刻才发第一个请求。如果装的时候这个点已经过了
（或预置数据已过期），装载后立刻补读一次真实的。

**前瞻窗口** = 版本结束日往前 15 天起。窗口内才做两件事：读预告 **1 小时一次**、
扫版区工具列表 **1 小时一次**。窗口外这两件事完全不查。

**拿到预告就停**：正文里写着准确开播时间（「2026年10月30日19:30」），拿到就不再问——
同一篇帖子问一百次也还是那个时间。

**拿到 act_id 之后**：开播前 3 小时起扫版区工具（10 分钟一次），按钮一出现就记下来并停。
随后按开播时间盯码：开播前 30 分钟到结束后 6 小时 **3 分钟**一次，其余 **30 分钟**一次。

**发码**要同时满足三条，缺一条都不发：

1. **码要齐**：接口返回几个码就等几个全部揭晓。直播中码是逐个放的，提前发就是残缺消息。
   > 不能写死「至少 3 个」：绝区零一般只发 **1 个码**。兜底是 `partial_grace_min`（默认 60 分钟）。
2. **要够晚**：`max(直播结束, 最后一个码揭晓) + post_delay_min` 之后。直播常超时，只认接口的 `live.end`。
3. **这一场没发过**（按 act_id + 码内容指纹去重，**按群 / 按人**分别记，后加的目标会自动补发当前场次）。

另外，直播开始超过 `stale_hours`（默认 48 小时）的场次一律不发。

> **补发窗口只有一两天。** 活动结束后接口直接返回 `-500012 活动已结束`。
> 实测结束 14 小时后码仍能完整读到，所以「当晚没发成、第二天早上补」来得及，再晚就没了。

## act_id 和版本周期从哪来

**act_id**（`ea202610261626345889` 这种）没法凭空生成，米哈游也没有「列出所有前瞻」的接口。
按优先级取，任一条走通就够：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 配置里手填 | `act_overrides`，一行一个 `hkrpg=ea2026...` |
| 2 | **自动发现** | 米游社版区那排工具按钮里的「直播兑换码」，跳转链接自带 act_id。只在前瞻前后约 29 小时出现 |
| 3 | **群里贴链接** | 谁把直播间链接发进群，插件自动接住 |
| 4 | 上次用过的 | 状态文件里的记录，同一场不会重复问 |

自动发现**星铁已实测**（4.7：按钮 10-30 18:00 上线、10-31 23:00 下线，比开播早 2 小时）。
原神和绝区零的工具列表都能读到（网页端 8 / 7 项，安卓端 10 / 10 项），但这两家的按钮
还没在窗口期里被亲眼验证过——窗口外三家都扫不到，属正常表现。真出现了插件自己会接住；
没出现就走「群里贴链接」这条路，不需要额外配置。

> 踩过的坑：同一个接口、同样的参数，请求头 `x-rpc-client_type` 不同返回的是两份**不同的工具表**。
> 不带这个头时原神直接返回 0 项、绝区零退回 7 项，看着像「版区没接导航」。所以插件网页端（`4`）
> 和安卓端（`2`）两份都问，谁给出带 act_id 的按钮就用谁。

**版本周期**不靠猜，读游戏内公告——那条「X.Y版本更新说明」的**结束时间就是版本结束时刻**，
也正是下一版的上线日：

```
星铁   4.7版本商店上新   → 2026-12-23 06:00   （4.7 共 42 天）
原神   7.2版本更新说明   → 2026-12-16 06:00   （7.2 共 42 天）
绝区零 3.3版本更新公告   → 2026-12-02 06:00   （3.3 共 42 天）
```

这个接口免登录、结构化、三家通用、不用 OCR。上一版的结束日就是这一版的开始日，
所以连着两个版本的公告能拼出完整周期；公告里只有一个版本时，起点取那条公告自己的发布时间。
版本号对不上就先不显示，等新版本上线后自动补上。

`/兑码状态` 里显示成 `本版周期：3.3 10-21 ~ 12-02（42 天） 进行中`，
没上线则显示 `下一版：4.7 11-11 ~ 12-23（42 天）` + `下一场前瞻预计：12-11 前后`。

## 依赖

- 取码、发码、读公告：**只用标准库 + AstrBot**，零第三方依赖。
- `rapidocr_onnxruntime`：**可选**，只给星铁「版本速览」长图 OCR 兜底用（公告接口挂了才走这条路）。
  会连带装 onnxruntime（约 45MB）和 opencv（约 108MB），小机器、树莓派、空间紧张就别装，
  不影响正事。装的话建议加 `--no-deps`，避免把 numpy / opencv 升到影响其它插件：
  ```bash
  pip install rapidocr_onnxruntime --no-deps
  ```

## 排查

| 现象 | 看这里 |
|---|---|
| 一直不发 | 日志搜 `[miyo_codes]`；多半是没拿到 act_id（`/兑码状态` 显示"未设置"） |
| 日志说"没有可用平台实例" | 平台没连上，或 `platform_id` 填错了；留空可自动探测 |
| 发了空消息 / 只发了一半 | `refreshCode` 只返回已揭晓的码，等直播结束再看 |
| 重复发 | 检查 `state_file` 是否可写；写不进去会每次都当新场次 |
| act_id 报"属于 xx 不是 xx" | 配置里串场了，改 `act_overrides` |
| 没显示版本周期 | ① 新版本还没上线（公告仍是上一版，属正常）；② 公告接口挂了，看日志 |
| 日志有 `retcode=1034` | 米游社详情接口限流，已自动冷却 5 分钟，半小时后重试 |
| 私聊发不出去 | 对方得是机器人好友；日志里会有 `发到 私聊xxx 失败` |

## 数据与隐私

- **群消息**：只匹配消息里的直播间链接、取出 `act_id`。不保存聊天内容、不上传、不做别的分析，
  `/兑码状态` 在群里执行时所有号码打码
- **本地文件**：只读写自己的状态文件（记「发过哪几场」「当前 act_id」），路径见 `state_file`
- **网络**：只连 `api-takumi.mihoyo.com`、`bbs-api.miyoushe.com`、`*-api.mihoyo.com` 等官方域名，
  用途只限查直播、查帖子、查公告；**没有任何第三方上报、遥测或统计**
- **不阻塞事件循环**：所有网络请求都是同步调用套在 `asyncio.to_thread` 里跑，单次超时 12~20 秒，
  卡住也只是那一轮晚点，不会把 AstrBot 的其它消息一起堵住
- **频率硬下限 60 秒**：配置填得比这更小也不生效。接口不是官方 API，一个人改成几秒，
  涨的是整个接口的压力，最后所有人的插件一起失效

## 更新日志

### v1.7.7 —— 调度重写：不该发请求的时候一个都不发

这一版重做了后台调度，三款游戏彻底解耦。（开发期分三轮迭代完成，合并为一次发布。）

**修复**

- **三个游戏互相打架**：原来共用一套「下次查什么」的时间戳，星铁进直播会把原神、绝区零
  的节奏一起带跑，一个停下另外两个也跟着停。现在按「游戏 × 资源类型」各自计时，互不影响
- **反复轮询已结束的活动**：活动结束后接口返回 `-500012`，插件原来会一直重问。现在识别到
  就标记为已结束、彻底跳过，`/兑码状态` 显示「已结束，不再查」
- **轮询任务可能没启动**：`create_task` 的异常被静默吞掉，表现为插件装好了却一动不动。
  现在启动时打一条「自动轮询已启动」心跳，异常也会进日志
- **拿到预告还每小时重问**：同一篇帖子的时间不会变，现在拿到即停
- **新装用户没有版本周期**：原来要等第一轮联网才有数据，期间什么都做不了。现在自带出厂预置，
  装的时候如果预置窗口已经过了（或数据过期），立刻补读一次真实的
- **提前进直播盯码**：码还没开始放就 3 分钟问一次，纯属浪费。现在只有开播前 30 分钟到
  结束后 6 小时才用快节奏
- **`/兑码状态` 与实际不符**：已结束的场次显示「未设置」、版本周期不标来源等问题一并修掉；
  新增「节奏」一行，一眼看出下一步什么时候动
- `terminate()` 改为先 cancel 再 await，避免重载插件时留下野任务

**改进**

- 删掉 `active_hours` 配置项——时段控制已由窗口推算取代，不再需要手工设时间段
- 窗口外不查预告、不扫版区；没有周期时的兜底间隔规范为 1~6 小时

更早版本（1.7.6 及以前）见 GitHub 提交记录。
